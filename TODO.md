# WledGW6205 — TODO

Possible follow-ups and improvements. Items are loosely ordered from
most-likely-useful to nice-to-haves. Check off as completed.

## Hardware / firmware coverage

- [ ] **Test on a longer chain.** Verified so far: 5 LEDs. The
      `rmt_write_items` approach should scale to hundreds without the
      underrun issues TestGW6205 hit, but we haven't actually measured
      the ceiling. Try 30, 100, 300. Watch the serial monitor for
      `Gw6205Bus` memory reports (36 items × 8 bytes ≈ 288 B per LED).
- [ ] **400 kHz GW6205 variant.** `Gw6205Bus` currently hard-codes the
      800 kHz bit timings. The slower variant just needs a runtime
      flag that doubles `T0H/T0L/T1H/T1L` ticks. Expose via the
      constructor and add a `TYPE_GW6205_400` to `const.h` +
      `bus_wrapper.h` if there's demand.
- [ ] **Port to ESP32-S3 / S2 / C3.** The legacy `driver/rmt.h` API
      we use works on plain ESP32 out of the box. Newer variants have
      a different RMT channel-memory model — on S3/C3 the default
      channel count is 4/2 respectively, and some methods behave
      differently. Would likely need an IDF-v5 `rmt_new_tx_channel` path.
- [ ] **Multiple GW6205 strips in parallel.** PolyBus tracks
      `_rmtChannel++` so a second bus should Just Work on a second
      channel, but the `mem_block_num = 2` in `Gw6205Bus::Begin()`
      consumes the neighboring channel's memory. Verify or bump to
      `mem_block_num = 1` if the first strip is short enough.
- [ ] **GRB / BRG at runtime.** `Gw6205ColorOrder` is already wired
      through the constructor but the `bus_wrapper.h` `create()` case
      hard-codes `GW6205_ORDER_RGB`. Pipe WLED's color-order field into
      it (instead of letting WLED's upstream GRB swap handle everything).

## Color pipeline

- [ ] **Gamma-aware 12-bit LUT.** Right now `expand8to12()` in
      `Gw6205Bus.h` uses bit replication: `(v<<4)|(v>>4)`. That's even
      across the range but doesn't leverage the perceptual benefit of
      12-bit — a gamma-2.2 or sRGB LUT of 256 uint16_t entries would
      give visibly smoother low-end ramps at ~0.5 KB flash cost.
- [ ] **Master brightness in the 12-bit domain** — already done
      (`Gw6205Bus::Show()` scales with rounding). Double-check the
      perception actually matches expectation with the slider.
- [ ] **Temporal dithering between 12-bit values.** When WLED's
      effects run their 8-bit internal math, the bottom 4 bits of our
      12-bit output are always zero. A simple per-frame dither pattern
      could recover an extra ~2 bits of perceived resolution.

## Build / dev experience

- [ ] **Measure flash savings.** Compare the WledGW6205 binary against
      a stock WLED build without `WLED_GW6205_ONLY`. Target was ≥100 KB
      savings from stripping NeoPixelBus template instantiations.
      Document the actual number in `patches_wled.md`.
- [ ] **Separate `_debug` build env.** Right now `-D WLED_DEBUG` is
      always on. Add a second env (`wled_gw6205_esp32_release`) with
      the flag removed so production builds are silent and ~10 KB
      smaller.
- [ ] **CI workflow.** GitHub Actions job that:
        1. Checks out upstream WLED at a known commit
        2. Runs `InstallPatches.bat` equivalent (bash)
        3. `pio run -e wled_gw6205_esp32`
        4. Reports binary size and any new warnings
      Catches upstream drift before it breaks your desk build.
- [ ] **Symlink alternative for NeoESP32RmtHI.** Windows users with
      developer mode on can `mklink /J` the local lib folder to
      `../wled/lib/NeoESP32RmtHI` instead of maintaining a copy. Add
      a `-Symlink` flag to `InstallPatches.bat`.
- [ ] **Pre-build UI check.** `html_*.h` headers must be generated by
      `npm run build` in `../wled/` before firmware compile. Detect
      the missing files in a PIO pre-script and emit a clear error
      instead of a cryptic "file not found".

## Upstream contribution

- [ ] **Submit `WLED_GW6205_ONLY` as `-DWLED_DISABLE_*` gates to WLED
      upstream.** The pattern we use could generalize: a
      `WLED_LED_TYPES_ALLOWLIST` mechanism that lets users strip
      unused drivers at compile time. Would benefit anyone building
      for flash-constrained boards.
- [ ] **PR NeoESP32RmtHI support for GW6205.** Add a
      `NeoEsp32RmtSpeedGw6205` class to the HI method library so the
      chipset fits the standard NeoPixelBus template pattern and
      doesn't need the `Gw6205Bus` side-channel.

## Known gotchas / things worth documenting

- [ ] **Dropbox-backed projects.** The `workspace_dir` override in
      `platformio.ini` points to `%LOCALAPPDATA%`. Document the
      equivalent for Linux/macOS (`~/.cache/pio_wled_gw6205`) and
      for other cloud-sync clients (OneDrive / Google Drive).
- [ ] **Adalight handshake `Ada` on boot.** Not a bug — WLED always
      prints it. Mention in README so future users don't panic.
- [ ] **Serial monitor flooded by `WLED_DEBUG`.** Once flash savings
      are measured, decide whether to keep debug on by default or
      switch to opt-in.
- [ ] **Upstream `.gitignore` vs our patches.** If upstream WLED adds
      files that coincidentally touch `const.h` / `bus_wrapper.h` /
      `bus_manager.cpp` in areas near our edits, `git apply` will
      conflict. The mechanical fix is in `patches_wled.md` but a
      more robust approach is `git apply --3way`.

## Long shots

- [ ] **Runtime 12-bit gamma curve editor.** Expose the LUT over the
      JSON API so users can tweak the curve without recompiling.
- [ ] **True RGBW / RGBWW support.** GW6205 is 3-channel only, but
      if variants with white channels exist, extend `Gw6205Pixel` to
      include a fourth `w` slot.
- [ ] **Signal analyzer capture.** Hook a logic analyzer to the data
      line and capture an actual frame with 3 known pixel values —
